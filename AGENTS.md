# understory — LLM-managed knowledge base (OKF spec)

## What this is
A personal knowledge base that follows the Open Knowledge Format: plain markdown concepts with YAML frontmatter, cross-linked into a graph and kept healthy by an internal LLM agent. An MCP server and a web UI query and change it. This repository is the REASON-labs fork (`origin`) of `thecodacus/understory` (`upstream`); the README's "What this fork adds" lists the differences.

## Stack
- **Node.js 20+** (monorepo via pnpm workspaces), **pnpm 10.15**, **TypeScript** everywhere
- **Vercel AI SDK v5** (`ai`) for the agent loop; **Express 5** for the server; **React + Vite** for the web UI; **simple-git** for history
- **Docker** for deployment (`docker-compose.yml`, port 3800)

## Monorepo structure
- `packages/core/` — the engine
  - `src/okf/` — the deterministic bundle layer: `bundle`, `knowledge-base` (transactions, git autocommit, run scopes), `search`, `graph`, `lint`, `indexer`, `logger`, plus provenance (`sources`, `history`, `tombstone`)
  - `src/agent/` — the LLM layer: `agent` (query, mutation, chat), `tools`, `system-prompt`, `dream` / `dream-review` / `dream-verify`, `deadline`, `forget`, `explain`, `hot-memory`, `query-cache`, `trace`
- `packages/server/` — MCP server and HTTP API: `app` (routes), `host` (single bundle or profiles), `access` / `auth` (tokens), `dreamer` (background dreaming), `profiles`, `api/*`, `mcp/*`
- `packages/web/` — the web UI
- `docs/TESTING.md` — the step-by-step rollout and soak guide
- `scripts/` — `rollout-test`, `make-test-bundle`, `dream-now`, `mcp-call`, `soak-report` (see the guide)
- `bench/` — recall benchmark; `sample-bundle/` — an example bundle

## Key commands
- `pnpm install && pnpm -r build` — build all packages (needed before running anything from `scripts/`)
- `pnpm test` — all tests (CI runs the same); `pnpm --filter @understory/core test` for one package
- `pnpm dev` — parallel dev mode
- `pnpm agent:query "..."` / `pnpm agent:mutate "..."` — smoke entries
- `node scripts/rollout-test.mjs <bundle>` — end-to-end on a temp COPY of a bundle, real model (`LLM_*` env)
- `docker compose up -d --build` — deploy on :3800

## Knowledge model
- A **concept** is a markdown file with frontmatter; only `type` is required. `index.md` (per directory) and `log.md` (root) are generated by code, never written by the model.
- Agent tools: read (`search_knowledge`, `read_concept`, `list_directory`, `lint_knowledge`) and write (`write_concept`, `patch_concept`, `delete_concept`). MCP tools: `memory_query`, `memory_add`, `memory_update`, `memory_status`, `memory_explain`, `memory_forget`, `memory_maintain`.
- **Tool-managed frontmatter.** The write tools, not the model, maintain `sources` (provenance, append-only; a run's own citation is kept to the newest 10), `history` (superseded facts, capped at 5) and `derived` (a machine-written synthesis). Model-supplied values for `history` and `derived` are ignored. Those keys are exempt from the plain-object frontmatter guard (`STRUCTURED_KEYS`).
- **Every mutation is a transaction** (`KnowledgeBase.transaction`): a failure restores the bundle. Runs also carry a `RunScope` (which concepts were touched, which commits were made). Unattended runs (dreams) add a change budget, deterministic verification (`verifyRun`), and rollback on the step limit.
- **A bundle is a git repo** (autocommit is on by default). State files in it: `.traces/` (run replays), `.forgotten.json` (hashes of forgotten sources), and `dream/<id>` branches for pending dream reviews.
- **Access.** `AUTH_TOKEN` is full access, `AUTH_TOKEN_READONLY` can only call the three read tools and make GET requests, a profile key is full access to its own memory. The read-only check is made on the request itself (`access.ts`).

## Things that bite
- **A new setting must be added in four places or it silently does nothing in Docker:** the code, `.env.example`, **both** compose files (they forward settings by name), and the README settings table. Empty values must mean "use the default".
- **stdio**: stdout is the MCP protocol stream, so anything logged by the stdio entry point goes to stderr.
- **Mocked tests cannot show prompt quality.** Tests mock the model at the AI SDK boundary; `deadline-sdk.test.ts` shows how to run the real SDK loop with a scripted model.
- **Windows**: git is slow (tests that use it set long timeouts), temp-dir cleanup needs `maxRetries`, and a git checkout may use CRLF, so compare file content with line endings normalised. Never create a test bundle inside this repository: git would autocommit into it (`make-test-bundle` refuses).
- **Generated source via shell heredocs** can lose backslashes in this environment; prefer the editor tools for regexes and escapes.

## Working agreements
How changes land here. Keep to these; they exist because a deep stack of PRs and an untested merge both cost us time.

1. **One item at a time.** Branch from `main`, finish and merge before starting the next. Avoid PRs stacked on PRs; if one item truly depends on another, merge the first first.
2. **Tests travel with the code.** New behaviour gets tests in the same PR. `pnpm -r build && pnpm test` must pass locally and in CI before merge.
3. **Docs travel with the code.** Update the README, `.env.example`, both compose files and `docs/TESTING.md` in the same PR as the behaviour they describe.
4. **Test the real thing, not just units.** Unit tests mock the model; they cannot tell you whether the prompt works. Add steps to `scripts/rollout-test.mjs` or `docs/TESTING.md` for each user-visible feature and run them against a COPY of a real bundle (they never touch the original).
5. **Never run destructive tools on the live bundle.** `memory_forget`, bulk updates and migrations are rehearsed on a copy first. Tools that delete default to a dry run.
6. **PRs state limits honestly.** What it does not cover, what is heuristic, what depends on model behaviour.
7. **Deploy at checkpoints, with a way back.** Back up the bundle, record the previous commit, then `git pull && docker compose up -d --build`. The bundle's own git history is the undo for content; the previous image commit is the undo for code.
8. **Sync with upstream about monthly** (`git fetch upstream`), as its own PR with nothing else in it; resolve conflicts by keeping both sides' behaviour and re-running the full suite.
